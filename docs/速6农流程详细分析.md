# 速6农（Speed Six Builder）流程详细分析

## 概述

"速6农"是项目中一个可选的加速模式，用于优先升级解锁第6个建筑工人所需的关键建筑。当用户在配置中开启"速6农模式"，脚本会自动：

1. 从游戏 JSON 数据中读取建筑/英雄/兵种等级
2. 在升级循环中自动提升这些目标建筑的优先级（覆盖用户设置的优先级）
3. 每次成功升级后回收临时优先级，下次循环重新计算

**`applyBuilderBaseOverride()` 算法详解：**

**文件：** `app/src/main/java/com/coc/zkqcode/jar/code/universal/buildings/upgrade/SpeedSixBuilderPriority.kt`  
**函数：** `applyBuilderBaseOverride()` (第 139 行)

```
输入: rawPriorityMap = {"箭塔": 5, "加农炮": 3, "多管迫击炮": 8, ...}
                    (用户在配置中设置的数字)

算法:

1. 收集未达标目标 (unmetTargets):
   - 战争机器: unlocked && level < 25 → 加入
   - 战斗直升机: unlocked && level < 20 → 加入
   - 多管迫击炮: unlocked && level < 9 → 加入
   - 箭塔: unlocked && level < 6 → 加入
   - 双管加农炮: unlocked && level < 4 → 加入

   注意: unlocked = false (未解锁/未建造) 的不加入！

2. 排序未达标目标 (sortedUnmet):
   战争机器 > 战斗直升机 > 多管迫击炮 > 箭塔 > 双管加农炮

3. 偏移策略 (shift = sortedUnmet.size):
   所有用户优先级值 + shift (避免碰撞)
   例如 shift=3: {"箭塔": 8, "加农炮": 6, "多管迫击炮": 11, ...}

4. 分配临时优先级:
   sortedUnmet[0] → priority = 1  (战争机器)
   sortedUnmet[1] → priority = 2  (战斗直升机)
   sortedUnmet[2] → priority = 3  (多管迫击炮)
   ...

5. 保存快照:
   将被覆写的原始值存入 InGameVars.speedSixOriginalPriorities[BaseType.Builder]

6. 返回新的 priorityMap

---
示例 (假设用户优先级 {"箭塔": 5, "加农炮": 3, "多管迫击炮": 8},
       未达标: 战争机器(level 20), 多管迫击炮(level 8), 战斗直升机(未解锁,需用户手动建造)):

unmetTargets = ["战争机器", "多管迫击炮"]  (战斗直升机未解锁,跳过)
sortedUnmet = ["战争机器", "多管迫击炮"]  (shift = 2)

结果:
  {"战争机器": 1, "多管迫击炮": 2,  "箭塔": 7, "加农炮": 5, ...}

升级顺序: 战争机器 → 多管迫击炮 → 加农炮 → 箭塔 → ...
```

## 四、关键判断逻辑

### `needsPriorityBoost()` — 是否需要优先级提升

**文件：** `SpeedSixBuilderPriority.kt` (第 60 行)

```kt
fun needsPriorityBoost(unlocked, level, target): Boolean =
    unlocked && level < target
```

**只有同时满足"已解锁"和"未达标"两个条件，才会被加入优先级提升列表。** 这是为了确保未建造的建筑不会获得无效的高优先级。

### `isUnmetForReport()` — 是否需要在报告中显示

**文件：** `SpeedSixBuilderPriority.kt` (第 67 行)

```kt
fun isUnmetForReport(unlocked, level, target): Boolean =
    !unlocked || level < target
```

**未解锁或未达标都算"未达标"，会在摘要消息中出现。** 区别是未解锁的显示为"未解锁"而非"x/y"格式。

### `consumeSnapshotForKey()` — 优先级快照消费

**文件：** `SpeedSixBuilderPriority.kt` (第 315 行)

```kt
fun consumeSnapshotForKey(baseType, name): Boolean {
    val snapshot = speedSixOriginalPriorities[baseType] ?: return false
    return snapshot.remove(name) != null  // 一次性消费
}
```

## 六、优先级覆盖算法总结

```
输入: 用户原始优先级表 + 全局状态变量
输出: 修改后的优先级表

步骤:
1. 从全局状态读取各建筑等级/解锁状态
2. 筛选出 needsPriorityBoost(unlocked=true, level<target) 的目标
3. 按预设顺序排序
4. shift = 未达标目标数量
5. 所有原始优先级值 + shift (向上偏移)
6. 未达标目标依次分配 1, 2, 3... 作为新优先级
7. 被覆写的原始值保存到快照
8. 每次升级成功后: 清除该建筑的快照
9. 下次 getOrderedList 调用时: 重新从配置文件读取 rawPriorityMap + 重新计算覆盖

关键保证:
- 速6农目标始终获得最高优先级 (值最小，排在最前面)
- 不会产生重复的优先级值 (偏移策略避免碰撞)
- 已达标建筑自动退出覆盖 (needsPriorityBoost 返回 false)
- 仅在升级成功时才消费快照 (失败则保留）
```
