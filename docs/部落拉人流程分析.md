# 部落拉人流程分析

> 基于 `ClanInvitePlayers.kt` 代码分析，辅助理解参考 `JoinClan.kt`、`MainBaseScript.kt`

---

## 一、整体定位

部落拉人（`clanInvitePlayers`）是主基地日常脚本（`playMainBase`）中的一个环节，在第 **61 行** 被调用，位于加入部落（`joinClan`，第60行）之后、请求增援（`requestReinforcement`，第62行）之前：

```
...
joinClan()         → 第60行：加入指定部落（可选）
clanInvitePlayers() → 第61行：拉人进自己部落
requestReinforcement() → 第62行：请求增援
...
```

通过开关 `Schema.MAIN_BASE_SETTINGS.INVITE_PLAYERS`（UI 配置项："邀请玩家" / "Invite Players"）控制启用/禁用。

## 二、流程总览

```
┌──────────────────────────────────────────────────────┐
│  前置检查：配置开关是否开启？                           │
│  否 → 直接 return true (跳过)                         │
└──────────────────────┬───────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────┐
│  步骤0：主页面检测是否已加入部落（新增）                │
│  图色检测 ClanInviteNotInClanFlag                     │
│  检测到（未入部落）→ 跳过拉人                         │
└──────────────────────┬───────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────┐
│  步骤1：读取配置                                      │
│  总轮次 Rounds + 每轮分钟数 RoundDuration             │
└──────────────────────┬───────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────┐
│  步骤2：多轮循环（for round in 1..totalRounds）       │
│                                                      │
│  ┌─────────── 每轮执行 ───────────┐                   │
│  │  2a. 进入部落页面（固定坐标）   │                   │
│  │  2b. 检测语言按钮 + 进入确认    │                   │
│  │  2c. 单轮时长循环（图色邀请）   │                   │
│  │      ├─ 检测到玩家项 → 邀请    │                   │
│  │      └─ 未检测到 → 滑动        │                   │
│  │  2d. 返回主页面                │                   │
│  └───────────────────────────────┘                   │
│                              ↑ 重复 totalRounds 次    │
└──────────────────────┬───────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────┐
│  结束：所有轮次完成                                   │
└──────────────────────────────────────────────────────┘
```

## 三、各步骤详细说明

### 步骤0：主页面检测是否已加入部落（新增）

```kotlin
val notInClan = findMultiColors(schema = MyColors.ClanInviteNotInClanFlag, increment = 1)
if (notInClan != null) {
    accountMessage("检测到未加入部落，跳过拉人任务")
    return true
}
```

- 在 **主页面** 执行，使用 `findMultiColors`（仅检测一次，非轮询）。
- 颜色模式 `ClanInviteNotInClanFlag`：
  - 区域：`(17, 404)` 到 `(83, 473)`
  - 主色：`#B6B5B7`
  - 辅助点阵：9 个偏移像素点
  - 匹配精度：0.9
- **检测到** → 当前账号未加入部落 → **跳过整个拉人任务**。
- **未检测到** → 账号已加入部落，继续执行。

> 此检测与 `JoinClan.kt` / `DonateToClan.kt` 中使用的 `NotJoinClanFlag` 不同，是独立的新颜色模式。

### 步骤1：读取配置

```kotlin
val totalRounds = getConfigRuntime(INVITE_PLAYERS_ROUNDS.key).toIntOrNull()
    ?: logAndRestart("...")
val roundDurationMinutes = getConfigRuntime(INVITE_PLAYERS_ROUND_DURATION.key).toIntOrNull()
    ?: logAndRestart("...")
```

| 配置键 | 显示名 | 默认值 |
|-------|-------|-------|
| `invite_players_rounds` | 拉人轮次 | 1 |
| `invite_players_round_duration` | 每轮时长(分钟) | 5 |

### 步骤2：多轮循环

#### 2a. 进入部落页面

```kotlin
TouchActions.tap(54, 46, delayTime = 800)
TouchActions.tap(753, 70, delayTime = 1200)
```

- 两个固定坐标点击，从主界面导航进入部落成员列表。
- 以 `720×1280` 分辨率为参考。

#### 2b. 检测语言按钮 + 确认进入

- 检测语言按钮（暂注释，国际版语言弹窗处理）。
- 通过图色 `ClanInvitePageEntryIndicator` 确认成功进入拉人页面。
- 若未检测到进入标志 → 跳过该轮（`continue` 到下一轮）。

#### 2c. 单轮时长循环

每轮内部运行一个基于时间的循环，持续 `roundDurationMinutes` 分钟：

```
图色检测 ClanInvitePlayerItemIndicator (区域 1068,517-1138,685)
  ├─ 检测到 → 点击玩家项 → 检测"更多信息"按钮
  │            ├─ 有 → 点击 → 检测"邀请确认"按钮 → 点击邀请
  │            │          → 检测返回标志 → 返回成员列表
  │            └─ 无（已关闭邀请）→ 跳过
  │            → 滑动列表
  └─ 未检测到 → 滑动列表
```

#### 2d. 返回主页面

```kotlin
if (!enterMainScreen()) return false
```

- 每轮结束时调用 `enterMainScreen()` 回到主界面。
- 失败则直接返回 `false` 终止整个拉人任务。

## 六、UI 配置项

| 配置键 | 显示名 | 类型 | 默认值 |
|-------|-------|------|-------|
| `invite_players` | 邀请玩家 | 开关 | 关 |
| `invite_players_rounds` | 拉人轮次 | 数字输入 | 1 |
| `invite_players_round_duration` | 每轮时长(分钟) | 数字输入 | 5 |

- `invite_players_rounds` 和 `invite_players_round_duration` 仅在 `invite_players` 开启后显示。

## 七、边界情况处理

| 情况 | 处理方式 |
|------|---------|
| 配置开关关闭 | 直接 return，跳过不执行 |
| 主页面检测到未加入部落 | `ClanInviteNotInClanFlag` 检测到 → 跳过整个拉人任务 |
| 某轮未成功进入拉人页面 | 跳过该轮（`continue`），不影响后续轮次 |
| 图色未检测到玩家项 | 直接滑动列表，继续循环 |
| 玩家已关闭被邀请功能 | 检测不到"更多信息"按钮 → 跳过，滑动到下一个 |
| 邀请成功后未检测到返回标志 | fallback 点击默认返回位置 `(176, 56)` |
| 某轮时间到 | 自动退出该轮循环，返回主页面，进入下一轮 |
| 配置轮次/时长不是数字 | `logAndRestart` 重启提醒 |
| `enterMainScreen()` 失败 | 返回 `false` 终止整个流程 |

## 八、变更记录

### v1 → v2（当前版本）

| 项目 | v1 | v2 |
|------|-----|-----|
| 前置检测 | 无 | 主页面检测 `ClanInviteNotInClanFlag`（未入部落则跳过） |
| 循环控制 | 单轮固定时长（`invite_players_duration`） | 多轮次（`rounds` × `round_duration`） |
| 配置项 | `invite_players_duration`（单值） | `invite_players_rounds` + `invite_players_round_duration` |
| 轮间逻辑 | 一次性 | 每轮结束返回主页面，重新进入下一轮 |
| 新增颜色 | `ClanInvitePlayerItemIndicator` | `ClanInvitePlayerItemIndicator` + `ClanInviteNotInClanFlag` |

### 原始版 → v1

| 项目 | 原始版 | v1 |
|------|--------|-----|
| 玩家检测方式 | OCR 识别序号（3种策略 fallback） | 图色检测 `ClanInvitePlayerItemIndicator` |
| 循环控制 | 固定 50 次 + 到底检测 | 用户配置运行时长 |
| 到底检测 | 有（通过OCR序号判断） | 无（时长到了自动结束） |
| 滑动时机 | 重复代码 | 抽成 `swipeList()` 复用 |
| OCR相关代码 | `TextRecognizer`、`extractIndexNumber` 等 | 全部删除 |
| 未使用的常量 | `INVITE_CONFIRM_TAP_COORDS`、`OcrRegion` | 已移除 |

## 九、相关功能补充

### 9.1 加入部落（JoinClan）

- 在拉人前执行（第60行），与拉人是**互补操作**。
- 支持两种模式：
  1. **未配置 TAG** → 检测 `NotJoinClanFlag`，若在部落外则自动搜索并申请加入随机部落。
  2. **配置了 TAG** → 通过 Android deep link 打开指定部落 → 申请加入。
- **24 小时冷却**：每天只执行一次。

### 9.2 请求增援（RequestReinforcement）

- 在拉人后执行（第62行）。
- 打开部落聊天 → 点击"请求增援"按钮。
- 最大尝试 5 次，每次间隔 200ms。
